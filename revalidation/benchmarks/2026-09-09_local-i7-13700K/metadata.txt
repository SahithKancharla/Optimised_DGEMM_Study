CAVEATS (same as the glogin run, repeated because they're easy to miss if you
only open this file):
- AVX2 numbers use avx/kernel_avx2.c and avx/strassen_avx2.c, which are
  correctness-verified ports but were NOT independently performance-tuned for
  AVX2 the way the original kernel.c/strassen.c were tuned for AVX-512 on the
  paper's Cascade Lake target. Don't read the AVX2 absolute numbers, or the
  blocked-vs-Strassen-AVX2 comparison, as representative of the real AVX-512
  build.
- Matrix data uses the paper's own A[i][j]=i+j, B[i][j]=i*j pattern (timing
  run, not a correctness run -- correctness was separately and exhaustively
  verified with asymmetric data; see ../../correctness/).
- This machine is NOT the paper's target (32-core Xeon Gold 5218, AVX-512).
  It's faster per-core and has a very different cache hierarchy and a
  heterogeneous P/E core layout, so absolute times and thread-scaling shapes
  are expected to differ from the paper on general principle, independent of
  any bug.
